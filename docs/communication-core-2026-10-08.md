# 通讯核心改进记录（2026-10-08）

本次继续现有 MCP 邮箱，目标是不同智能体工具之间直接收发消息。没有增加运行依赖、数据库迁移或单独服务。

## 收件与回执

- `mailbox_inbox(limit, cursor)` 直接查询当前账号未完成的收件，按写入顺序分页。旧历史超过 100 条、对话超过 100 个、读过但没有处理，都不会使收件消失。
- `pending_total` 和工具附带的 `pending.count` 都统计未完成收件。完成、取消、失败是终态，仍可在对话历史查看。
- `reply_message` 成功时，在同一事务中将原收件标记完成；发送失败不会确认原消息。重复相同状态回执不重复写入或增加处理次数。
- 消息返回 `expects_reply`。这是发件人的期待，接收方仍按正文决定如何答复。通知只确认状态，不发送新的“收到”消息。
- Codex Shell 取信后备入口复用同一查询，支持 `--limit` 和 `--cursor`，不会注册或替换已有会话身份。

## 派发

- 对同一收件账号的一批直连投递，在 SQLite 事务中一起抢占，只发送一次取信唤醒；每条消息仍保留各自投递 ID 与结果。
- 多个 Broker 竞争同一批时，已被抢占的消息不会再次唤醒。新消息在后续批次到达，仍可能产生后续唤醒；本次没有增加跨批次的持久唤醒租约。
- 离线消息保留并延后扫描，不消耗重试次数；新连接恢复离线积压。派发查询按收件账号轮转，避免单个账号积压占满批次。
- 抢占时重新检查重试时间和处理终态，避免提前重试或再次唤醒已处理的消息。全局暂停会停止自动派发。
- 没有直连通道的适配器仍按每条投递发事件；这些事件携带各自的投递 ID，不能当成同一条消息丢弃。

## 会话身份与 DSH-B

账号重连沿用三元身份 `(host_type, host_instance_id, native_session_id)`。注册/恢复审计现在记录身份和前后名称，实际更名另有 `account.renamed`。`whoami.database_path` 用于确认各工具连接的是不是同一数据库。

现场数据库共有四个账号：DSH-A、TRAE-A、codex-A、Codex-Paperclip-review；包括软删除记录的查询也没有 DSH-B。源码没有自动删除账号的路径。旧交接文件记载曾因填错会话 ID 创建过 DSH-B，但当前审计不足以还原其后来消失的原因。此次没有重新创建或恢复 DSH-B，也没有把缺失原因当作已修复。

## 后续验收修正：名称、身份与恢复

安装器新邮箱模式统一注册 `mcp-agent-mailbox`；旧 `board` / `board-mcp` 仅在启动参数
确认为本邮箱模块时迁移。其他服务器保留，`--legacy` 明确保留旧公告板名称。
已安装邮箱的禁用、超时、自定义环境、动态转发变量和工具权限保留；新旧名称同时存在时
保留新项设置，清除确认指向邮箱的旧项，避免重复启动。安装状态检查使用相同名称规则。

Python 3.11+ 使用标准库 `tomllib`；Python 3.10 条件依赖轻量 `tomli` 用于安全解析安装
配置，安装器和锁文件均已声明。此条件依赖不增加单独服务或后台进程。

同一 `MailboxConnection` 的身份在首次绑定后固定。重复提交相同身份不创建账号、不推进
连接代次、不替换 provider；不同身份明确拒绝，原绑定和后续发送者不变。即便旧连接
失效后需要重绑，也不能将旧连接上下文改成另一会话。

客户端重启恢复的最小路径：宿主启动该会话的独立 MCP 子进程，注入稳定的宿主类型、
实例与原生会话 ID；启动注册自动找到原账号并开启新连接。如果宿主不注入身份，只能在
该会话独立连接上再次 `connect_mailbox`。服务不根据最近账号、显示名、同软件其他会话或
未验证的 PID 推断身份。一个共享全局 MCP 进程不能通过轮流注册承担多个会话；应在宿主
适配层提供独立连接或已验证的逐请求会话上下文后再实现自动恢复。

`tools/connect_codex_host.py` 是显式身份/PID 的宿主桥接，用于恢复存在会话的连接与投递；
它不表示该聊天的原生 MCP 工具目录已加载。聊天存在、邮箱主连接在线、可主动取信和
可被唤醒须分别核验，不能将连接过期描述成原聊天或账号不存在。
